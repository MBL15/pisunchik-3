# ФСП · Оренбургская область — `// КОД СТАЛ СПОРТОМ_`

Прототип единой цифровой платформы регионального отделения Федерации спортивного программирования
Оренбургской области (кейс «ОренКод 2026»). Монорепозиторий из трёх FastAPI-микросервисов, общающихся
по async HTTP (`httpx`), и серверного UI на Jinja2 + Tailwind CSS (тёмная тема, Clean Web + Neo-Brutalism).

## Быстрый старт

```bash
pip install -r requirements.txt
py run_all.py            # Windows (python run_all.py на Linux/macOS)
```

Откройте **http://localhost:8000**. Оркестратор поднимает `sportsman_service → competition_service → gateway_service`,
ждёт `/health` каждого, мультиплексирует логи с цветными префиксами и включает live-reload
(`--no-reload` — отключить). Каждый сервис засевает свою in-memory «БД» при старте; любая правка кода
перезапускает сервис и возвращает демо-данные к исходному состоянию.

| Демо-аккаунт       | Роли                   | Пароль    |
|--------------------|------------------------|-----------|
| `admin@fsp56.ru`   | Федерация + Судья      | `fsp2026` |
| `trainer@fsp56.ru` | Тренер + Судья         | `fsp2026` |
| `athlete@fsp56.ru` | Спортсмен + Тренер     | `fsp2026` |

Это основные аккаунты; всего их 12 (спортсмены с разными сроками, санкциями, представителем, судьи) —
полный список со сценариями в [базе знаний](docs/knowledge-base/07-demo-data.md).
На странице входа есть кнопки быстрого входа. Все персональные данные фиктивны.

## Дизайн-система (стиль ФСП России)

Интерфейс повторяет визуальный язык fsp-russia.ru: графитовый фон `#1B1C21`, фирменный `#402FFF`
(сплошные блоки, кнопки, жёсткие тени при hover), светлый `#EDEDED` (плавающая шапка-«остров», плашки-даты),
акцент `#EC1D35` (LIVE, узлы логотипа), заголовки JetBrains Mono тонкого начертания + Inter для текста,
скругления 6/12px, пунктирные «чертёжные» линии, rail-коннекторы с узлами, duotone-иконки дисциплин.
Интерактивный слой: печатающийся заголовок `// КОД СТАЛ СПОРТОМ_`, терминал с реальными `/health` сервисов,
анимированные «дорожки» платы в hero, живой протокол (демо-раунд зациклен), сдвиг карточек + тень `#402FFF`.
Токены: `tailwind.config` в `base.html` (`fsp-*`) и `gateway_service/static/app.css`. Для текста на тёмном
используется светлый тон `#8C80FF` (контраст ≥ 4.5:1), а `#402FFF` — только для заливок/рамок.
Логотип — собственный знак «молекула» в духе ФСП; официальный логотип можно взять из брендбука ФСП.

## Архитектура

```
gateway_service      :8000  UI (Jinja2+Tailwind), сессии и активная роль, API-шлюз, QR-документы
   │ httpx
   ├── sportsman_service   :8001  реестр, выдача ФСП ID, связи тренер↔спортсмен, санкции, сроки, история
   └── competition_service :8002  календарь, заявки, парсер логов → протокол, рейтинг, справки
           └─ httpx → sportsman_service (санкции, ФИО, возраст, привязки тренера)
shared/              справочники (RU), формат ФСП ID, http-клиент, демо-ростер
```

* **Сессия** — подписанная HMAC cookie `{fsp_id, active_role}`. Роль заново сверяется с реестром на каждом
  запросе: переключение роли (`POST /role`) не требует повторного входа, права проверяются по активной роли.
* **Деградация** — если сервис недоступен, страницы рендерятся с предупреждением `[WARN]`, а не падают.
* **API-шлюз** — `GET /api/public/{service}/{path}` проксирует только allowlist (календарь, протоколы,
  рейтинг, проверка справок, статистика); реестр с ПДн наружу не публикуется.
* Внутренние сервисы доверяют шлюзу (ролевые проверки — в gateway). В проде — mTLS/служебные токены.

### Ключевые алгоритмы
* **ФСП ID** — `FSP-56-YY-NNNNN-C`: регион, год регистрации, порядковый номер, контрольная цифра Луна
  (`shared/fsp_id.py`). Валидацию используют оба сервиса, выдачу — только `sportsman_service`.
* **Протокол из одобренных заявок** — федерация вносит показатели (ICPC: решено + штраф; score: баллы; DSQ),
  в протокол допускаются только участники с одобренной заявкой, места считает `rank_manual` тем же движком,
  что и для логов. Публикация → `FINISHED`, рейтинг, история спортсменов, справки.
* **Парсер протоколов** (`competition_service/log_parser.py`) — формат `FSP-LOG/1`: `JOIN`, `RUN <задача> <вердикт>`,
  `SCORE <баллы>`, `DSQ "<причина>"`. ICPC: решённые ↓, штраф ↑ (минута AC + 20 за отклонённую попытку, CE не штрафуется).
  Score: сумма баллов жюри. Ранжируются все участники, равные делят место, DSQ — без места. Строки с неверной
  контрольной цифрой отклоняются с предупреждением.
* **Рейтинг** (`competition_service/rating.py`, чистые функции) — сумма баллов по таблице кейса (100/80/60 … 40/30/20)
  × **1.2**, если призовое место (1–3, не DSQ) минимум на двух соревнованиях сезона; спортсмены с действующей
  дисквалификацией/отстранением исключаются; участники других регионов не рейтингуются. По каждой строке видны
  исходные результаты, баллы, формула и причина применения коэффициента. Таблица и коэффициент настраиваются федерацией.

## Модель данных (кратко)

| Сущность | Сервис | Поля |
|---|---|---|
| Person | sportsman | fsp_id, ФИО, пол, дата рождения, муниципалитет, организация, roles[], disciplines[], rank{code, assigned_at, expires_at, order_no}, judge_category{code, expires_at}, sanctions[], guardian, pd_consent_at |
| TrainerLink | sportsman | trainer_fsp_id, athlete_fsp_id, discipline, status (PENDING/ACTIVE/SUSPENDED/ENDED), history[] |
| Competition | competition | code, title, discipline, level, type, format (+note), calendar_plan (ЕКП/региональный) + номер, даты, место, возрастная группа, status, registration_deadline, judges[] |
| Protocol | competition | source (manual/upload/live/seed), results[] (ручной ввод), raw_log[], names snapshot, entries[] (place, status, solved, penalty, score, tasks), published |
| Application | competition | competition_id, athlete_fsp_id, submitted_by, status, decided_at |
| Document | competition | number, verification_code (HMAC), person, competition, result, purpose |

## API (основное, Swagger: `:8001/docs`, `:8002/docs`)

**sportsman_service** — `GET/POST /api/v1/persons`, `GET /api/v1/persons/{fsp_id}`, `POST /api/v1/persons/lookup`,
`POST /api/v1/auth/verify`, `GET /api/v1/sanctions/active`, `GET /api/v1/alerts/ranks`, `GET /api/v1/alerts/judge-categories`,
`GET /api/v1/trainers/{fsp_id}/athletes?with_performance=true`, `GET /api/v1/athletes/{fsp_id}/links`,
`POST /api/v1/links`, `POST /api/v1/links/{id}/status`, `GET /api/v1/persons/{fsp_id}/performance`, `GET /api/v1/stats`, `GET /api/v1/audit`.

**competition_service** — `GET/POST /api/v1/competitions`, `GET /api/v1/competitions/{id}/protocol`,
`GET …/protocol/entry-sheet`, `POST …/protocol/results`, `POST …/protocol/ingest`, `POST …/live/tick`, `POST …/protocol/publish`, `GET /api/v1/results`,
`GET /api/v1/rating`, `GET/PUT /api/v1/rating/settings`, `GET/POST /api/v1/applications`, `POST /api/v1/applications/{id}/decision`,
`GET /api/v1/judges/{fsp_id}/assignments`, `GET /api/v1/dashboard`, `POST /api/v1/documents/participation`,
`GET /api/v1/documents/{number}`, `GET /api/v1/documents/{number}/verify`, `GET /api/v1/audit`.
