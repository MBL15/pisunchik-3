# 1. Продукт, роли и пути пользователя

## Задача

Региональное отделение ФСП ведёт спортсменов, тренеров и судей в шести дисциплинах, проводит соревнования
и формирует сборную по рейтингу. Платформа заменяет таблицы и переписку одной системой:

- единый реестр с ФСП ID и мультиролями (один человек — спортсмен и тренер, тренер и судья);
- календарь стартов (ЕКП и региональный план; очно, онлайн, смешанно);
- заявки с автоматической проверкой допуска и модерацией;
- протоколы, которые собираются из лога соревнования, а не вручную;
- прозрачный рейтинг сезона с объяснением каждого балла;
- контроль сроков разрядов и судейских категорий;
- справки об участии с QR-кодом и публичной проверкой подлинности.

Дисциплины: алгоритмическое программирование (ALG), продуктовое (PRD), информационная безопасность (SEC),
искусственный интеллект (AI), робототехника (ROB), беспилотные авиационные системы (UAV).

## Роли

| Роль | Код | Что может |
|---|---|---|
| Спортсмен | `athlete` | Подавать заявки на себя, подтверждать/отклонять привязку тренера, видеть историю и рейтинг, получать справки |
| Тренер | `trainer` | Отправлять запросы на привязку по ФСП ID, видеть подопечных и сроки их разрядов, подавать заявки за подопечных с активной привязкой |
| Судья | `judge` | Видеть свою категорию и её срок, назначения и историю судейства |
| Федерация | `admin` | Модерация заявок, контроль сроков, живой протокол и публикация, загрузка логов, настройки рейтинга, создание соревнований, справки, журнал действий |

Роль `admin` выдаёт только федерация; при регистрации можно выбрать `athlete`, `trainer`, `judge`
(`SELF_SERVICE_ROLES`). Активная роль переключается в шапке (`POST /role`) без повторного входа;
права проверяются по активной роли на каждом запросе.

## Публичная часть

| Страница | Путь | Суть |
|---|---|---|
| Навигатор | `/` | Hero с терминалом реальных `/health`, события, «с чего начать», дисциплины, живой протокол, рейтинг, география, «один аккаунт — все роли» |
| Календарь | `/calendar` | Фильтры по дисциплине, плану, формату; предстоящие, live, завершённые |
| Рейтинг | `/rating` | По дисциплине и сезону, фильтры возраст/разряд, раскрываемая формула по каждому спортсмену, блок исключённых |
| Регистрация | `/register` | Мультироль, согласие 152-ФЗ, законный представитель для < 18 лет, выдача ФСП ID сразу |
| Вход | `/login` | Форма + 12 кнопок быстрого входа по сценариям |
| Проверка справки | `/verify/{номер}?c={код}` | Публичная проверка HMAC-подписи справки |

## Кабинеты: путь пользователя

Принцип всех кабинетов — «сверху вниз»: сначала то, что требует действия, затем текущие процессы,
затем справочная информация. Разделы пронумерованы, а закреплённая навигация подсвечивает текущий раздел
и показывает счётчики.

### Спортсмен (`cabinet_athlete.html`)

1. **01 · Что сделать сейчас** — приоритизированный список: действующая санкция → запрос тренера
   на привязку (Подтвердить / Отклонить) → истекающий разряд (если заявка уже подана — ссылка на неё,
   иначе «Выбрать старт») → приглашение в команду → открытый приём заявок. Если дел нет — «Всё в порядке».
2. **02 · Мои старты** — карточки заявок с трекером из 4 шагов
   (Заявка → Допуск → Старт → Результат) и подсказкой, что происходит сейчас; ниже старты, на которые
   можно подать заявку в один клик (с «приём ещё N дней»); свёрнутый список неподходящих по возрасту.
3. **03 · История выступлений** — плашка (стартов, призовых, побед, баллов), подсказка до ×1.2,
   таблица со ссылкой на протокол, полоской баллов и кнопкой «Справка» (номерной документ для печати/PDF с QR-кодом).
4. **04 · Тренеры и документы** — «Мои дисциплины» (выбор из шести, командные — алгоритмика, продуктовая, CTF и ИИ — помечены; команды спортсмена), мои тренеры, законный представитель (для несовершеннолетних), антидопинг
   (дата курса РУСАДА и ссылка на сертификат — форма в карточке, ссылки на rusada.ru), документы (согласие на
   обработку ПДн с датой, согласие представителя), этап спортивной подготовки.

Календарь (`/calendar`) фильтруется по дисциплине, плану, формату и возрастной группе; вошедшему спортсмену у каждого
старта видно «вы проходите по возрасту», флажок «Только мои» оставляет его дисциплины и возраст.

**Уведомления** — колокольчик в шапке у любой роли (`/notifications`, число новых, поиск и «только непрочитанные») + Telegram, если подключён.

**Работа с большими списками (федерация).** Реестр (`/registry`), модерация заявок (`/applications`: фильтры со счётчиками,
массовое одобрение/отклонение с комментарием), журнал действий (`/audit`: поиск, автор, период, выгрузка), календарь
(поиск, статус, уровень, сезон; завершённые — по страницам). Во «Входящих» кабинета — первые 6 заявок и ссылка на модерацию.

Этап заявки вычисляет шлюз (`_cabinet_athlete`):
`4` — по соревнованию уже есть результат (уходит в историю), `3` — одобрена и старт наступил,
`2` — одобрена, `1` — подана. Отклонённые показываются с комментарием федерации.

После подачи заявки пользователь попадает на `/cabinet#starts`, новая карточка подсвечивается,
запускаются конфетти (флаг `celebrate` во flash).

### Тренер (`cabinet_trainer.html`)

1. **01 · Сроки действия разрядов подопечных** — карточки подопечных с разрядом ≤ 90 дней или истёкшим;
   в каждой — полоска оставшегося срока и форма «Подать заявку на подтверждение» прямо в карточке
   (только подходящие открытые старты, без уже поданных). Если подопечный уже подал заявку сам —
   показывается её статус вместо формы. Ниже — кто ещё не подтвердил привязку.
2. **02 · Заявка и привязка** — заявка за любого подопечного; запрос на привязку по ФСП ID.
3. **03 · Мои спортсмены** — таблица со статусом связи, разрядом и сроком, стартами/призовыми, баллами,
   действиями (пауза, завершить, возобновить, отозвать).
4. **04 · Поданные заявки** — заявки, поданные тренером, со статусами.

### Судья (`cabinet_judge.html`)

Предупреждение об истечении категории (карточка-задача) → **01 · Назначения** → **02 · Мои соревнования**.

### Федерация (`cabinet_admin.html`)

Кабинет разбит на вкладки по смыслу работы (`/cabinet?tab=…`); на вкладке — метка с числом дел, ждущих решения,
внутри — быстрый переход к её разделам.

| Вкладка | `tab` | Что на ней |
|---|---|---|
| **Обзор** | `overview` (по умолчанию) | KPI сезона, быстрые действия, **Входящие** (заявки на старты — первые 6 и ссылка на `/applications`, разряды и судейские категории, «внести результаты», «назначить главного судью»), **Контроль сроков** (разряды, категории, приём заявок, сроки отчётов `REPORT_DEADLINES`, в т.ч. премия Губернатора до 1 февраля), последние записи **журнала** |
| **Соревнования** | `competitions` | Новое соревнование и **справочник типов**, **Приём заявок** (ручное открытие / закрытие / продление), **Судейские коллегии** |
| **Протоколы и результаты** | `results` | **Автоматические протоколы** (ввод результатов участников с одобренными заявками → черновик с местами → публикация; live; загрузка лога), **Требования ЕВСК**, **Справка об участии** с QR |
| **Рейтинг и сборные** | `rating` | **Управление рейтингом** (баллы, коэффициент, минимум призовых), **Сборные команды** (набор из рейтинга, список и проект приказа) |
| **Отчёты и реестр** | `reports` | Отчёт о численности с выгрузками; переходы в **реестр** (`/registry`), **модерацию заявок** (`/applications`), **журнал действий** (`/audit`) |

Действия федерации возвращают на вкладку своего раздела (`admin_url("registration")` → `/cabinet?tab=competitions#registration`);
старые ссылки вида `/cabinet#registration` скрипт страницы переводит на нужную вкладку.

**Подсказки для новичков.** На каждой странице при первом посещении предлагается необязательный тур (можно пропустить или отключить навсегда);
кнопка «?» внизу справа и клавиша «?» запускают его снова. Подробности — в [UI и дизайн-системе](06-ui-design-system.md#удобство-интерактивный-тур-и-общие-приёмы).

## Сквозные сценарии кейса и где их показать

| Сценарий | Как показать |
|---|---|
| Регистрация мультиролевого пользователя и выдача ФСП ID (Д1) | `/register` → баннер с ФСП ID и контрольной цифрой |
| Переключение ролей без повторного входа | `trainer@` → переключатель «Тренер / Судья» в шапке |
| Тренер: сроки разрядов и заявка в один шаг | `trainer@` → карточка Григорьева → «Подать заявку на подтверждение» |
| Спортсмен: привязка тренера | `hasanov@` → «Подтвердить» |
| Спортсмен: заявка и путь до результата | `hasanov@` → «Подать заявку» → трекер этапов |
| Федерация вносит результаты → протокол из одобренных заявок → история (С5) | `admin@` → «Внести результаты: Кубок «OrenCTF Осень»» → решено/штраф → «Сформировать и опубликовать» → протокол по форме; `hasanov@` → «История выступлений» |
| Федерация: модерация → live → публикация → рейтинг | `admin@` → модерация, «Опубликовать» live-протокол, `/rating` |
| Прозрачный рейтинг с ×1.2 и исключением санкционированных | `/rating?discipline=ALG` (Соколов 222.0, Жуков в исключённых) |
| Справка с QR и проверкой подлинности (Д10) | Кабинет спортсмена → «Справка» → QR → `/verify/...` |
| Отчёт о численности занимающихся с динамикой за 2 года, выгрузка .xlsx | `admin@` → «Отчёты» → `/reports/headcount` → XLSX / DOCX / PDF |
| Сборная из рейтинга, список и проект приказа | `admin@` → `/rating?discipline=ALG` → отметить спортсменов → «Сформировать сборную» → `/teams/{id}` → «Проект приказа» → «Утвердить состав» |
| Подсветка по требованиям ЕВСК | `admin@` → «ЕВСК» (Валиева — I разряд при истекающем II); любой опубликованный протокол → колонка «ЕВСК» (видна только федерации) |
| Справочник типов соревнований | `admin@` → «Новое соревнование» → «Справочник типов» → добавить «Фестиваль» → он появился в форме создания |
| Ручное закрытие и открытие приёма заявок | `admin@` → «Приём заявок» → «Закрыть приём»; `trainer@` пытается подать заявку — отказ; «Открыть приём» с новой датой |
| Выгрузка документов | Протокол `/protocols/{id}` и кабинет спортсмена / тренера («Отчёт о соревнованиях»): XLSX · DOCX · PDF |
