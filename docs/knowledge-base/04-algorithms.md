# 4. Алгоритмы

Движки — чистые функции без I/O, поэтому покрыты unit-тестами (`tests/test_engines.py`).

## Парсер логов FSP-LOG/1 (`competition_service/log_parser.py`)

Одно событие на строку, `#` — комментарий, первая строка-заголовок задаёт параметры:

```text
#! FSP-LOG/1 competition=ОРБ-ALG-2026-01 mode=icpc tasks=8 penalty=20
00:00:00 JOIN  FSP-56-25-00008-7
00:12:44 RUN   FSP-56-25-00008-7 A WA
00:19:02 RUN   FSP-56-25-00008-7 A OK
01:40:00 DSQ   FSP-56-25-00010-3 "Нарушение регламента"
00:00:00 SCORE FSP-56-26-00021-9 31.50
```

| Событие | Синтаксис | Действие |
|---|---|---|
| `JOIN` | `ЧЧ:ММ:СС JOIN <ФСП ID>` | Участник появляется в протоколе |
| `RUN` | `… RUN <ФСП ID> <задача A–Z> <OK\|WA\|TL\|RE\|ML\|CE>` | Попытка по задаче |
| `SCORE` | `… SCORE <ФСП ID> <баллы>` | Баллы жюри (суммируются) |
| `DSQ` | `… DSQ <ФСП ID> "<причина>"` | Дисквалификация в протоколе |

Параметры заголовка по умолчанию: `mode=icpc`, `tasks=8`, `penalty=20`.

Устойчивость к ошибкам: нераспознанная строка и строка с невалидным ФСП ID (контрольная цифра)
пропускаются с предупреждением `Строка N: …`; протокол всё равно собирается. Пустой результат — `422`.

### Ранжирование

**ICPC** (ALG, SEC в демо-данных):

- задача решена при первом `OK`; попытки после `OK` и вердикт `CE` не учитываются;
- штраф по задаче = минута первого `OK` + `penalty` × число неудачных попыток до него;
- сортировка: решённые ↓, суммарный штраф ↑, время последнего `OK` ↑;
- **равные места делят** участники с одинаковыми (решённые, штраф): 1, 2, 2, 4.

**Score** (PRD, AI, ROB, UAV): сортировка по сумме баллов ↓, равные суммы делят место.

**DSQ**: участник остаётся в протоколе со статусом `DSQ`, без места, в конце таблицы (по ФСП ID).

Результат: `ParsedLog(mode, meta, entries, warnings, events, last_time)`.

### Live-протокол

У сидированного live-соревнования (ALG5, id 5) лог разделён на «уже произошедшее» и очередь `live_queue`.
`POST …/live/tick` добавляет 2 события не чаще раза в 1.5 с (`LIVE_TICK_MIN_INTERVAL`), чтобы много
открытых вкладок не «перематывали» поток. Когда очередь иссякает, демо-раунд перезапускается со
стартового снимка (`live_replay`). Браузер опрашивает `/partials/live/{id}` каждые 2.5 с, опрос
останавливается в фоновой вкладке и после `data-live-done`. Публикация забирает остаток очереди в протокол.

## Протокол из одобренных заявок (ручной ввод)

Основной путь по кейсу: соревнование прошло, федерация вносит результаты, протокол формируется сам.

- **Кто попадает в протокол** — только участники с `APPROVED`-заявкой на это соревнование
  (`store.approved(cid)`). Чужой ФСП ID в запросе — `422`; заявки на модерации в лист ввода не попадают,
  после одобрения участник появляется в нём автоматически.
- **Что вносится** — итоговые показатели без лога задач: ICPC — решено и штраф в минутах; score — сумма
  баллов жюри; флаг DSQ с причиной. Отметка «не явился» исключает участника из протокола.
- **Ранжирование** — `log_parser.rank_manual()` строит записи той же формы, что и `parse_log`, и отдаёт их
  в общий `rank_entries()`: те же правила сортировки, деления мест и DSQ без места. В ICPC без лога нет
  времени последней сдачи, поэтому равные (решено, штраф) делят место.
- **Протокол** хранится с `source="manual"` и `results[]`; `store.reparse` пересчитывает его так же, как
  протоколы из логов (баллы рейтинга, смена настроек).
- **Сверка с заявками** выполняется для любого протокола соревнования, у которого есть заявки: участник
  региона без одобренной заявки и одобренный участник без результата дают предупреждения `[WARN]`.
- **Публикация** (флаг `publish` или `POST …/protocol/publish`) переводит соревнование в `FINISHED`,
  результаты попадают в рейтинг, историю спортсменов и справки.

Ввод разрешён после начала соревнования, до публикации и не для live-протокола, который ведётся из лога.

## Рейтинг сезона (`competition_service/rating.py`)

```
рейтинг = Σ base_points(уровень, место)   по опубликованным протоколам сезона и дисциплины
        × коэффициент стабильности (1.2)   если призовое место (1–3, не DSQ) на ≥ 2 соревнованиях
```

Таблица баллов по умолчанию (`DEFAULT_POINTS_TABLE`, рекомендации кейса; федерация может изменить):

| Уровень | 1 место | 2 место | 3 место |
|---|---|---|---|
| Чемпионат России | 100 | 80 | 60 |
| Первенство России | 80 | 60 | 40 |
| Межрегиональные | 60 | 45 | 30 |
| Региональные | 40 | 30 | 20 |

Правила:

- 4-е место и ниже, DSQ — 0 баллов; DSQ не считается призовым;
- участники других регионов (`RR ≠ 56`) не рейтингуются;
- спортсмены с действующей санкцией выводятся отдельно (`excluded`) с причиной;
- итог округляется до 0.1 (`ROUND_HALF_UP`, через `Decimal`);
- порядок: итог ↓, победы ↓, призовые ↓, ФИО; одинаковые (итог, победы, призовые) делят позицию;
- для каждой строки отдаётся `breakdown` (соревнование, место, баллы, призовое ли), `coefficient_reason`,
  `bonus` — UI показывает формулу по каждому спортсмену.

Сезон = год окончания соревнования. Фильтры API: возрастная группа и минимальный разряд.
Настройки (`PUT /api/v1/rating/settings`) меняют таблицу, коэффициент и минимум призовых; после сохранения
все протоколы перепарсиваются (`store.reparse`), базовые баллы в протоколах и истории пересчитываются.

Контрольный пример из e2e: Соколов (ALG) — (40 + 0 + 45 + 100) × 1.2 = **222.0**.

## Подсветка по требованиям ЕВСК (`competition_service/evsk.py`)

Чистые функции. Результат выполняет требование разряда, если на соревновании уровня L спортсмен занял место не ниже N,
а в протоколе не менее M участников; DSQ результата не даёт. Таблица `(разряд → [(уровень, N, M)])` —
`EVSK_REQUIREMENTS` в `shared/domain.py`.

> Пороги в таблице **рабочие**: они масштабированы под размеры демо-протоколов и не заменяют действующую ЕВСК
> (приказ Минспорта России). Перед боевым использованием сверьте и поправьте только эту таблицу; МС автоматически
> не подсвечивается.

`GET /api/v1/evsk/candidates` берёт спортсменов региона из протоколов за 365 дней (черновики — тоже, идущие
live-соревнования — нет), для каждого результата находит **высший** подходящий разряд и сравнивает с текущим:

| Состояние | Когда |
|---|---|
| `assign` | подходящий разряд выше текущего (или разряда нет) |
| `confirm` | совпадает с текущим, срок которого истёк или ≤ 90 дней |
| `have` | уже есть такой или выше — не подсвечивается |
| `unknown` | реестр недоступен, текущий разряд не сверен |

Спортсмены с действующей санкцией не попадают в выдачу. Подсветка: раздел «ЕВСК» кабинета федерации, колонка
«ЕВСК» в протоколе (только экранная версия для федерации, в печать и публичный протокол не выводится), плашки
в черновике протокола. Рядом видно, подана ли заявка на разряд.

## Численность занимающихся (`sportsman_service/headcount.py`)

Чистая функция `build_report(persons, today, years, …)`. Занимающийся на конец года Y — спортсмен реестра с
`start_year ≤ Y` (данных о выбытии нет). Отчётная дата прошлых лет — 31 декабря, текущего — сегодня; возраст и
разряд берутся на эту дату (разряд — по текущей записи профиля: `assigned_at ≤ дата` и срок не истёк, поэтому в
прошлых годах он занижен). Разрезы: дисциплины (спортсмен считается в каждой своей — сумма больше итога),
муниципалитеты, организации, возрастные группы (`HEADCOUNT_AGE_BANDS`), пол, разряды. Для каждой строки — значения
по годам, `delta` и `delta_pct` (`None`, если база нулевая); в сводке — ещё «начали заниматься в течение года».
Фильтры: дисциплина, муниципалитет, организация; период 2–6 лет (по умолчанию 3 отчётных даты = динамика за 2 года).

## Выгрузка документов (`gateway_service/exports.py`, `reports.py`)

Один документ — один `Doc` (шапка, реквизиты, заголовки, абзацы, таблицы, подписи); три рендерера дают файлы:
`openpyxl` (.xlsx, числа остаются числами), `python-docx` (.docx, шапка таблицы повторяется на страницах),
`reportlab` (.pdf, A4, нумерация страниц). Для PDF нужен TTF-шрифт с кириллицей: ищутся Arial (Windows/macOS),
DejaVu и Liberation (Linux) либо `FSP_PDF_FONT` / `FSP_PDF_FONT_BOLD`; не найден — `503` с пояснением.
Построители в `reports.py`: протокол соревнования, численность занимающихся, список сборной, проект приказа,
отчёт о соревнованиях спортсмена. Имя файла отдаётся в `Content-Disposition` с ASCII-запасным вариантом и `filename*`.

## История выступлений спортсмена

`sportsman_service._compile_performance()` запрашивает у competition опубликованные результаты по списку ФСП ID
и считает `starts`, `podiums`, `golds`, `best_place`, `season_points`; результаты сортируются по дате ↓.
Если competition недоступен — `{"available": false}`, и UI показывает «история недоступна».

## Справка и проверка подлинности

- Номер: `56-{год}-{seq:05d}`.
- Код: `HMAC-SHA256(SECRET_KEY, "номер|fsp_id|competition_id")[:12].upper()`.
- QR ведёт на `{PUBLIC_BASE_URL}/verify/{номер}?c={код}`; проверка — `hmac.compare_digest`.
- Подделка кода или номера даёт `INVALID` (e2e проверяет оба случая).
- QR генерируется в SVG (`gateway_service/qr.py`, библиотека segno).

## Подписанные cookie

`sign(payload)` = `base64url(JSON) + "." + HMAC-SHA256(SECRET_KEY)[:32]`; `unsign` сверяет подпись через
`compare_digest`. Используется для сессии и flash.
