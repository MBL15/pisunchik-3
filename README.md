# ФСП · Оренбургская область — `// КОД СТАЛ СПОРТОМ_`

Прототип единой цифровой платформы регионального отделения Федерации спортивного программирования
Оренбургской области (кейс «ОренКод 2026»). Монорепозиторий из четырёх FastAPI-микросервисов, общающихся
по async HTTP (`httpx`), и серверного UI на Jinja2 + Tailwind CSS (тёмная тема, Clean Web + Neo-Brutalism).

Пять ролей (спортсмен, тренер, судья, федерация, министерство) с мультиролью и переключением без повторного входа;
все обязательные требования ТЗ и дополнительные сценарии Д1–Д12; сверх кейса — биржа программистов, личные токены,
JSON API `/api/me/v1` и MCP-серверы для моделей, интерактивные туры и режимы доступности.

## Быстрый старт

Нужен **Python ≥ 3.12** (на 3.10–3.11 `run_all.py` не запустится: f-строки с `\`). Проверено на 3.13 и 3.14; CI гоняет тесты на 3.12 и 3.13.

```bash
pip install -r requirements.txt
py run_all.py            # Windows (python run_all.py на Linux/macOS)
py -X utf8 run_all.py    # на консоли cp1251/cp866: баннер с рамками иначе роняет запуск
```

Для выгрузки в PDF нужен шрифт с кириллицей (Arial, DejaVu или Liberation находятся сами; иначе `FSP_PDF_FONT=/путь/к/шрифту.ttf`).

Откройте **http://localhost:8000**. Оркестратор поднимает `sportsman_service → competition_service → market_service → gateway_service`
(порты 8001, 8002, 8003, 8000), ждёт `/health` каждого, мультиплексирует логи с цветными префиксами и включает live-reload
(`--no-reload` — отключить). Каждый сервис засевает свою in-memory «БД» при старте; любая правка кода
перезапускает сервис и возвращает демо-данные к исходному состоянию.

**Всё в Docker** (Postgres + четыре сервиса, состояние сохраняется между запусками):

```bash
docker compose up -d --build     # http://localhost:8000; сброс данных: docker compose down -v
```

Наружу публикуется только шлюз, внутренние сервисы закрыты служебным токеном, Postgres слушает только `127.0.0.1:5432`.
Порты 8000–8003 должны быть свободны. Деплой на сервер за nginx и Telegram через туннель — в [runbook](docs/knowledge-base/08-dev-runbook.md).

Настройки берутся из окружения или файла `.env` в корне (в репозиторий он не попадает):

| Переменная | Назначение |
|---|---|
| `FSP_DATABASE_URL` | Postgres (`postgresql://fsp:fsp@127.0.0.1:5432/fsp`); пусто — состояние только в памяти |
| `FSP_SECRET_KEY` | подпись cookie сессии и кодов справок; вне localhost обязателен (иначе шлюз не стартует) |
| `FSP_PUBLIC_BASE_URL` | публичный адрес шлюза (для ссылок, OIDC, `Secure`-cookie при https) |
| `FSP_SERVICE_TOKEN` | служебный токен шлюза для внутренних сервисов; пусто — проверка выключена |
| `FSP_TELEGRAM_TOKEN`, `FSP_TELEGRAM_BOT`, `FSP_TELEGRAM_PROXY` | Telegram-уведомления, прокси для `api.telegram.org` |
| `FSP_DEMO_TODAY`, `FSP_DEMO_SCALE` | зафиксировать «сегодня» (`YYYY-MM-DD`); добавить N синтетических людей для проверки больших списков |
| `FSP_PDF_FONT`, `FSP_PDF_FONT_BOLD` | TTF-шрифт с кириллицей для PDF |

## Дизайн-система (стиль ФСП России)

Интерфейс повторяет визуальный язык fsp-russia.ru: графитовый фон `#1B1C21`, фирменный `#402FFF`
(сплошные блоки, кнопки, жёсткие тени при hover), светлый `#EDEDED` (плавающая шапка-«остров», плашки-даты),
акцент `#EC1D35` (LIVE, узлы логотипа), заголовки JetBrains Mono тонкого начертания + Inter для текста,
скругления 6/12px, пунктирные «чертёжные» линии, rail-коннекторы с узлами, duotone-иконки дисциплин.
Интерактивный слой: печатающийся заголовок `// КОД СТАЛ СПОРТОМ_`, терминал с реальными `/health` сервисов,
анимированные «дорожки» платы в hero, живой протокол (демо-раунд зациклен), сдвиг карточек + тень `#402FFF`.
Токены: `tailwind.config` в `base.html` (`fsp-*`) и `gateway_service/static/app.css`. Для текста на тёмном
используется светлый тон `#8C80FF` (контраст ≥ 4.5:1), а `#402FFF` — только для заливок/рамок.
Логотип — собственный знак «молекула» в духе ФСП; официальный логотип можно взять из брендбука ФСП.

## Архитектура

```
gateway_service      :8000  UI (Jinja2+Tailwind), сессии и активная роль, публичный API, /api/me/v1, OIDC, QR-документы
   │ httpx
   ├── sportsman_service   :8001  реестр, выдача ФСП ID, связи тренер↔спортсмен, санкции, сроки, история,
   │                              организации и клубы, группы, нормативы, команды, личные токены
   ├── competition_service :8002  календарь, заявки, парсер логов → протокол, рейтинг, справки,
   │       │                      апелляции, премии, интеграции и вебхуки
   │       └─ httpx → sportsman_service (санкции, ФИО, возраст, привязки тренера)
   └── market_service      :8003  биржа программистов: анкеты с портфолио и навыками, отклики с проектами
mcp_fsp/, mcp_market/   MCP-серверы (stdio): тонкие обёртки над API шлюза для моделей
shared/              справочники (RU), формат ФСП ID, http-клиент, демо-ростер, листинг, Postgres-персистентность
```

Хранение двухрежимное: без `FSP_DATABASE_URL` — в памяти с сидом при старте, с ним — Postgres (JSONB-снимки, запись после
каждого не-GET запроса). Подробнее — [архитектура](docs/knowledge-base/02-architecture.md).

* **Сессия** — подписанная HMAC cookie `{fsp_id, active_role}`. Роль заново сверяется с реестром на каждом
  запросе: переключение роли (`POST /role`) не требует повторного входа, права проверяются по активной роли.
* **Деградация** — если сервис недоступен, страницы рендерятся с предупреждением `[WARN]`, а не падают.
* **API-шлюз** — `GET /api/public/{service}/{path}` проксирует только allowlist (календарь, протоколы,
  рейтинг, проверка справок, статистика); реестр с ПДн наружу не публикуется.
* Внутренние сервисы доверяют шлюзу (ролевые проверки — в gateway); при заданном `FSP_SERVICE_TOKEN` принимают только
  запросы со служебным токеном. В проде — mTLS/ротация токена.
* **Уведомления** — лента в кабинете и Telegram-бот (`gateway_service/notify.py`; за блокировкой хостинга — через прокси или обратный SSH-туннель).

### Ключевые алгоритмы
* **ФСП ID** — `FSP-56-YY-NNNNN-C`: регион, год регистрации, порядковый номер, контрольная цифра Луна
  (`shared/fsp_id.py`). Валидацию используют оба сервиса, выдачу — только `sportsman_service`.
* **Протокол из одобренных заявок** — федерация вносит показатели (ICPC: решено + штраф; score: баллы; DSQ),
  в протокол допускаются только участники с одобренной заявкой, места считает `rank_manual` тем же движком,
  что и для логов. Публикация → `FINISHED`, рейтинг, история спортсменов, справки.
* **Парсер протоколов** (`competition_service/log_parser.py`) — формат `FSP-LOG/1`: `JOIN`, `RUN <задача> <вердикт>`,
  `SCORE <баллы>`, `DSQ "<причина>"`. ICPC: решённые ↓, штраф ↑ (минута AC + 20 за отклонённую попытку, CE не штрафуется).
  Score: сумма баллов жюри. Ранжируются все участники, равные делят место, DSQ — без места. Строки с неверной
  контрольной цифрой отклоняются с предупреждением.
* **Рейтинг** (`competition_service/rating.py`, чистые функции) — сумма баллов по таблице кейса (100/80/60 … 40/30/20)
  × **1.2**, если призовое место (1–3, не DSQ) минимум на двух соревнованиях сезона; спортсмены с действующей
  дисквалификацией/отстранением исключаются; участники других регионов не рейтингуются. По каждой строке видны
  исходные результаты, баллы, формула и причина применения коэффициента. Таблица и коэффициент настраиваются федерацией.

| Group, Session | sportsman | группа организации по этапу подготовки (зачисление, перевод) и журнал занятий (очно / онлайн, подтверждение) |

| QualificationRequest | sportsman | kind (RANK/JUDGE_CATEGORY), person, code, purpose (присвоение/подтверждение), basis (соревнование и результат), status, order_no |

| Protocol | competition | source (manual/upload/live/seed), results[] (ручной ввод), raw_log[], names snapshot, entries[] (place, status, solved, penalty, score, tasks), published |
| Application | competition | competition_id, athlete_fsp_id, submitted_by, status, decided_at |
| Team | competition | title, discipline, season, purpose, фильтры рейтинга, members[] (снимок: место, баллы, разряд, тренеры; MAIN/RESERVE), status DRAFT/APPROVED, order_no, order_date |
| CompetitionType | competition | справочник типов (title, число использований); пополняется федерацией |
| Document | competition | number, verification_code (HMAC), person, competition, result, purpose |

## API (основное, Swagger: `:8001/docs`, `:8002/docs`, `:8003/docs`; внешние: `/api/ext/v1/docs`, `/api/market/v1/docs`)

**sportsman_service** — `GET/POST /api/v1/persons`, `GET /api/v1/persons/{fsp_id}`, `POST /api/v1/persons/lookup`,
`POST /api/v1/auth/verify`, `GET /api/v1/sanctions/active`, `GET /api/v1/alerts/ranks`, `GET /api/v1/alerts/judge-categories`,
`GET /api/v1/reports/headcount`, `GET /api/v1/organizations`, `POST /api/v1/persons/{fsp_id}/antidoping`,
`GET/POST /api/v1/notifications`, `POST /api/v1/notifications/read`, `GET/POST /api/v1/qualification-requests`, `GET /api/v1/trainers/{fsp_id}/athletes?with_performance=true`, `GET /api/v1/athletes/{fsp_id}/links`,
`POST /api/v1/links`, `POST /api/v1/links/{id}/status`, `GET /api/v1/persons/{fsp_id}/performance`, `GET /api/v1/stats`, `GET /api/v1/audit`.

**competition_service** — `GET/POST /api/v1/competitions`, `GET /api/v1/competitions/{id}/protocol`,
`GET …/protocol/entry-sheet`, `POST …/protocol/results`, `POST …/protocol/ingest`, `POST …/live/tick`, `POST …/protocol/publish`, `GET /api/v1/results`,
`GET /api/v1/rating`, `GET/PUT /api/v1/rating/settings`, `GET/POST /api/v1/applications`, `POST /api/v1/applications/{id}/decision`,
`POST /api/v1/competitions/{id}/registration`, `GET/POST/DELETE /api/v1/competition-types`, `GET /api/v1/evsk/{requirements,candidates}`,
`GET/POST /api/v1/teams`, `PUT/DELETE /api/v1/teams/{id}`, `POST /api/v1/teams/{id}/{members,approve}`,
`GET /api/v1/rating/organizations` (рейтинг клубов), `GET /api/v1/judges/{fsp_id}/assignments`, `GET /api/v1/dashboard`, `POST /api/v1/documents/participation`,
`GET /api/v1/documents/{number}`, `GET /api/v1/documents/{number}/verify`, `GET /api/v1/audit`.

**Внешние и ролевые API шлюза** — `GET /api/public/…` (allowlist без ПДн); `/api/me/v1` — JSON API от имени человека в его роли,
токен `Authorization: Bearer fspu_…` выпускается на `/api-access` ([подробно](docs/knowledge-base/12-api-mcp.md)); `/api/ext/v1` — интеграции
внешних систем (токены `fspi_…`, вебхуки); `/api/market/v1` — биржа (токены `fspm_…`); OIDC — `/.well-known/openid-configuration`.

**MCP для моделей** — `py -X utf8 -m mcp_fsp` (платформа по ролям, нужен `FSP_API_TOKEN`) и `py -X utf8 -m mcp_market` (биржа, токен `fspm_…`, см.
[биржа](docs/knowledge-base/10-market.md)); конфиг `mcpServers` для `mcp_fsp` показан на странице `/api-access`.

## Тесты

```bash
py -m unittest -v              # движки, сервисы через TestClient, выгрузки, API и MCP (стек не нужен; без FSP_DATABASE_URL)
py -X utf8 tests/e2e_smoke.py  # сквозные сценарии через шлюз (нужен запущенный run_all.py)
```

В репозитории около 270 юнит-тестов в 27 файлах; CI (`.github/workflows/tests.yml`) гоняет их на Python 3.12 и 3.13.
E2E меняет данные — перед демонстрацией перезапустите стек. Проверка неопределённых имён: `py -m pyflakes gateway_service sportsman_service competition_service shared tests`.
